Task 5: Logic-LM on a Prolog knowledge base
Bharat Marimuthu, AIEA Lab (Faithful NeSy Reasoning)

For this task I joined the Faithful NeSy Reasoning team and studied Logic-LM (Pan, Albalak, Wang and Wang, Findings of EMNLP 2023). The paper starts from the observation that large language models often reach conclusions their own reasoning does not support. It proposes splitting the job in two. A problem formulator uses few-shot prompting to turn a natural-language problem into a symbolic program. A symbolic reasoner then solves that program deterministically: a logic-programming engine, a first-order prover, a constraint solver, or a SAT solver, depending on the problem type. A result interpreter maps the solver's output back to an answer. If the program fails to run, a self-refiner feeds the solver's error message back to the model and asks it to fix the program. With GPT-4 across five logical reasoning benchmarks, the paper reports an average gain of 39.2% over standard prompting and 18.4% over chain-of-thought. The gain grows as the number of reasoning steps increases.

I first ran the authors' released code on the logic programs GPT-4 had already generated. For ProntoQA, ProofWriter, LogicalDeduction and AR-LSAT, my execution rates and execution accuracies match the paper's Table 3. I skipped FOLIO because it needs the Prover9 binary, which I did not compile. This step reproduces only the solver and evaluation half of the pipeline, since generating new programs requires model versions that have been retired.

I then reimplemented the full pipeline on the gym-exercise knowledge base from Task 4. Pyke is replaced by SWI-Prolog, called from Python through Janus. The formulator, result interpreter and self-refiner (up to three rounds) follow the paper's structure and prompt format. I wrote 14 questions, with gold answers generated by running reference queries in Prolog. Running the pipeline with those reference queries in place of the model gives 14 of 14, which checks the solver and evaluation code. With llama3.2 running locally at temperature 0, Logic-LM answered 10 of 14 correctly, compared with 6 for direct prompting and 4 for chain-of-thought. Self-refinement raised the share of programs that ran from 93% to 100%. Logic-LM got all nine easier questions right but only one of the five harder ones. These numbers come from one small model on a small question set, so I read them as an illustration, not a benchmark result. Chain-of-thought scoring below direct prompting, the opposite of the paper's GPT-4 result, is partly an artifact of this model: on four questions it began writing Prolog and repeated it until the token limit, never giving an answer. One practical lesson was that llama3.2 copied the first few-shot example for every question when the whole prompt was sent as a single message. Sending the examples as separate user and assistant turns fixed this.

The most useful result for the team is how Logic-LM failed. All four of its errors were programs that ran without error but meant something different from the question. One dropped a condition, one added a condition the question did not contain, one placed a negation incorrectly, and one combined conjunction and disjunction without parentheses. Self-refinement cannot catch these, because it only responds to solver errors. In the negation case it fixed the error and kept the wrong meaning. Two answers counted as correct were also right only by chance: the query swapped its arguments, matched nothing, and the empty result happened to equal the gold answer "false." So a symbolic solver guarantees that the answer follows from the program, but not that the program says what the question asked. That gap between a program that runs and a faithful translation is what I would like to work on with the team, for example by checking translations against the knowledge base's argument types, or by translating back to English and comparing with the original question.

Code, run outputs and a step-by-step README are in the project repository. The paper is at arxiv.org/abs/2305.12295 and the authors' code at github.com/teacherpeterpan/Logic-LLM.
